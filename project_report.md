# Отчет по проекту MathEduNew

## 1. Создание образовательной веб-платформы

### Цели и задачи проекта

Проект MathEduNew представляет собой веб-платформу для проведения интерактивных уроков математики. Система предназначена для учителей и учеников: учитель создает уроки, добавляет задания, запускает обычные занятия или дуэльный режим, а ученик решает задания в браузере, получает проверку ответа, может перерешать ошибки и видеть собственный прогресс.

Основная цель проекта - автоматизировать проведение математических занятий и сделать проверку заданий более быстрой, персонализированной и удобной.

Основные задачи системы:

- регистрация и авторизация пользователей с разными ролями;
- создание классов, учеников и уроков;
- добавление заданий вручную или через шаблоны;
- автоматическая генерация индивидуальных вариантов заданий;
- проверка числовых, строковых и алгебраических ответов;
- сохранение ответов и прогресса учеников;
- возможность "Решить еще раз" с новым вариантом задания;
- генерация домашних заданий по ошибкам ученика;
- подключение ИИ для объяснений и проверки спорных ответов;
- проведение математических дуэлей между учениками;
- просмотр результатов, рейтингов и статистики.

### Технологический стек

Backend:

- Python - основной язык разработки.
- Flask - веб-фреймворк для маршрутов, страниц и API.
- PostgreSQL - база данных для хранения пользователей, уроков, заданий и результатов.
- psycopg2 - подключение к PostgreSQL.
- Jinja2 - шаблонизация HTML-страниц.
- SymPy - математическая проверка и упрощение выражений.
- OpenAI API - генерация объяснений, помощь ученику и создание домашних заданий.
- WeasyPrint / FPDF - формирование PDF-документов с домашними заданиями.

Frontend:

- HTML, CSS, JavaScript - интерфейс платформы.
- Fetch API - обмен данными между страницей и сервером.
- MathJax - отображение математических формул.
- Marked.js - отображение Markdown-ответов от ИИ.

Структура проекта:

- `app.py` - главный серверный файл Flask-приложения.
- `math_engine.py` - генерация параметров задач и математические вычисления.
- `task_generator.py` - сборка готовых вариантов заданий из шаблонов.
- `templates/` - HTML-шаблоны страниц.
- `static/js/` - клиентская логика для ученика, учителя, дуэлей и редактора.
- `static/css/` - стили интерфейса.
- `schema_pg.sql` - структура базы данных.
- `services/` - вспомогательные сервисы.
- `platform_admin_routes.py` - маршруты администратора платформы.
- `devtools/` - инструменты для разработки и тестирования шаблонов.

## 2. Архитектура системы

### Общая схема работы

Система построена по классической клиент-серверной архитектуре.

Пользователь работает с HTML-страницей в браузере. JavaScript на странице отправляет запросы к Flask API. Сервер обрабатывает запрос, обращается к базе данных, генерирует задания или проверяет ответы, после чего возвращает HTML-страницу или JSON-ответ.

Основные уровни:

1. Интерфейс пользователя:
   - страницы ученика;
   - страницы учителя;
   - страницы администратора;
   - модальные окна, формы, кнопки проверки и повторного решения.

2. Серверная логика:
   - маршруты Flask;
   - проверка доступа;
   - генерация заданий;
   - сохранение результатов;
   - подсчет статистики;
   - работа с ИИ.

3. Математическое ядро:
   - генерация параметров;
   - подстановка параметров в шаблоны;
   - вычисление правильного ответа;
   - сравнение ответа ученика с правильным.

4. База данных:
   - пользователи;
   - классы;
   - уроки;
   - задания;
   - варианты заданий;
   - ответы учеников;
   - дуэльные раунды и матчи.

app = Flask(__name__)

### 3.7. Генерация параметров задачи

Файл: `math_engine.py`

Класс `MathEngine` отвечает за генерацию значений параметров.

Главная функция:

```python
def generate_parameters(template_params, conditions='', band=None, forced_choice_idx=None):
```

Она проходит по описанию параметров и генерирует числа или выбирает значения из набора.

Поддерживаются типы:

- `int` - целые числа;
- `float` - дробные числа;
- `choice` - выбор значения из списка;
- ограничения `multiple_of`;
- условия генерации через `conditions`.

Важная часть:

```python
if forced_choice_idx is not None:
    idx = int(forced_choice_idx)
else:
    start, end = MathEngine._band_slice(choice_len, band)
    idx = random.randrange(start, end)
```

Этот код позволяет либо случайно выбрать набор параметров, либо принудительно выбрать конкретный набор. Это используется при повторном решении, чтобы ученик получил не тот же вариант, а связанный с ним новый.

### 3.8. Генерация готового задания

Файл: `task_generator.py`

Класс `TaskGenerator` превращает шаблон в готовое задание.

Главная функция:

```python
def generate_task_variant(template, band=None, forced_choice_idx=None):
```

Она выполняет несколько шагов:

1. Проверяет, что в шаблоне есть вопрос, ответ и параметры.
2. Вызывает `MathEngine.generate_parameters()`.
3. Подставляет параметры в текст вопроса.
4. Подставляет параметры в формулу ответа.
5. Упрощает ответ через SymPy.
6. Возвращает готовый вариант.

Возвращаемый объект:

```python
return {
    'question': question,
    'correct_answer': answer,
    'params': params,
    'template_id': template.get('id'),
    'choice_idx': choice_idx
}
```

Поле `choice_idx` важно: оно показывает, какой набор параметров был выбран. Потом этот индекс сохраняется в базе и используется для повторного решения.

### 3.9. Запуск урока учеником

Файл: `app.py`

Маршрут:

```python
@app.route('/lesson/<int:lesson_id>')
def start_lesson(lesson_id):
```

Когда ученик открывает урок, сервер:

1. Проверяет, имеет ли ученик доступ к уроку.
2. Загружает данные урока.
3. Загружает список заданий.
4. Проверяет, есть ли уже сохраненный вариант задания для этого ученика.
5. Если варианта нет - генерирует новый.
6. Сохраняет вариант в `student_task_variants`.
7. Передает задания в шаблон `student_lesson.html`.

Сохранение индивидуального варианта выглядит так:

```python
json.dumps({
    'params': params,
    'generated_question': question,
    'computed_answer': computed_answer,
    'initial_choice_idx': choice_idx,
    'current_choice_idx': choice_idx,
    'is_retry': False
})
```

Это нужно для честности урока: если ученик обновит страницу, он увидит тот же вариант, а не новый случайный пример.

### 3.10. Проверка и сохранение ответа

Файлы:

- `app.py`
- `static/js/student_lesson.js`

На клиенте ученик вводит ответ и нажимает кнопку проверки. JavaScript отправляет данные на сервер:

```javascript
await fetch('/save_answer', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
        task_id: taskId,
        answer: answer,
        is_correct: isCorrect,
        retry_used: retryUsed
    })
});
```

На сервере маршрут `/save_answer` сохраняет ответ в таблицу `student_answers`.

Функция учитывает:

- был ли ответ правильным;
- был ли это обычный ответ или повторное решение;
- есть ли уже сохраненный ответ;
- нужно ли обновить статус на правильный;
- нужно ли пересчитать прогресс ученика.

Повторное решение отмечается через `retry_used`. Если ученик решил правильно только со второй попытки, система может засчитать частичный балл.

### 3.11. Проверка математических ответов

Файл: `app.py`

Главная функция:

```python
def _check_answer_core(user_answer, correct_answer, answer_type='numeric'):
```

Она проверяет разные типы ответов:

- числовые ответы;
- дроби;
- интервалы;
- строки;
- алгебраические выражения;
- списки значений.

Для алгебры используется SymPy:

```python
expr1 = simplify(sympify(ua_mod.replace("^", "**")))
expr2 = simplify(sympify(ca_mod.replace("^", "**")))
return simplify(expr1 - expr2) == 0
```

Это позволяет засчитать математически равные выражения, даже если ученик записал ответ в другой форме.

### 3.12. Повторное решение "Решить еще раз"

Файлы:

- `app.py`
- `static/js/student_lesson.js`

На странице ученика кнопка "Решить еще раз" открывает модальное окно. JavaScript запрашивает новый вариант:

```javascript
const response = await fetch(`/api/generate_retry_task/${taskId}`);
```

На сервере работает маршрут:

```python
@app.route('/api/generate_retry_task/<int:task_id>')
def generate_retry_task(task_id):
```

Он:

1. Находит задание и шаблон.
2. Загружает старый вариант ученика из `student_task_variants`.
3. Берет исходный индекс набора `initial_choice_idx`.
4. Считает парный индекс для повторного решения.
5. Генерирует новый вариант с `forced_choice_idx`.
6. Сохраняет retry-вариант.

Вспомогательная функция:

```python
def get_retry_choice_idx(variant_data, template_params):
    initial_choice_idx = variant_data.get('initial_choice_idx')
    choice_len = get_choice_len(template_params)
    if choice_len and choice_len > 1:
        return initial_choice_idx, (initial_choice_idx + choice_len // 2) % choice_len
```

Идея такая: если у задания 4 набора параметров, то ученик с набором 1 получает набор 3, а ученик с набором 2 получает набор 4. Так повторное решение не повторяет старую задачу, но остается в той же логике сложности.

### 3.16. Режим математической дуэли

Файлы:

- `app.py`
- `templates/student_duel.html`
- `templates/duel_bracket.html`
- `static/js/student_duel.js`

Дуэльный режим превращает урок в соревнование между учениками. В системе есть раунды, матчи, сетка и таблица лидеров.

Основные серверные маршруты:

- `/api/duel/<lesson_id>/rounds` - создание и получение раундов;
- `/api/duel/<lesson_id>/start` - запуск дуэли;
- `/api/duel/<lesson_id>/my_match` - получение матча ученика;
- `/api/duel/match/<match_id>/answer` - отправка ответа;
- `/api/duel/<lesson_id>/next-round` - переход к следующему раунду;
- `/api/duel/<lesson_id>/leaderboard` - таблица лидеров;
- `/api/duel/<lesson_id>/bracket` - турнирная сетка.

На клиенте `student_duel.js`:

- запускает таймер;
- отправляет ответы;
- скрывает результат до конца раунда;
- опрашивает счет соперника;
- показывает итоги после завершения.

Проверка ответа в дуэли проходит так:

1. Сначала сравнивается нормализованный ответ.
2. Затем вызывается `/api/check_answer`.
3. Если ответ сложный, используется ИИ-проверка.
4. Ответ сохраняется в `duel_match_answers`.

### 3.17. Администрирование платформы

Основные функции:

- проверка прав администратора платформы;
- список школ;

Такое разделение удобно, потому что обычная логика уроков находится в `app.py`, а административная часть не смешивается с основными сценариями ученика и учителя.

## 6. Особенности реализации

### Индивидуальные варианты заданий

Каждый ученик получает свой вариант задания. Вариант сохраняется в базе, поэтому при обновлении страницы задание не меняется. Это защищает урок от случайной смены данных и делает проверку стабильной.

### Адаптация сложности

Функция `infer_student_mark()` определяет уровень ученика. Затем `MathEngine._band_slice()` выбирает часть набора параметров по уровню. Так можно выдавать ученикам задания подходящей сложности.

### Повторное решение

Повторное решение не просто повторяет старое задание. Система берет связанный набор параметров и генерирует новый вариант. Это помогает ученику исправить ошибку на похожем примере.

### Математическая проверка

Система проверяет не только точное совпадение строк, но и математическую эквивалентность. Например, выражения могут быть записаны по-разному, но считаться одинаковыми после упрощения.

### Интеграция с ИИ

ИИ используется не как основная проверка, а как дополнительный помощник:

- объясняет ошибки;
- разбирает решение;
- помогает проверить спорный ответ;
- формирует индивидуальные домашние задания.

### Дуэльный режим

Дуэльный режим добавляет соревновательную механику: ученики решают задания на время, система считает очки, определяет победителя и строит таблицу лидеров.

## 7. Результат

В результате разработана образовательная веб-платформа для проведения уроков математики. Проект объединяет обычные уроки, автоматическую генерацию вариантов, проверку ответов, аналитику, ИИ-помощника, домашние задания и соревновательный режим.

Система позволяет учителю быстрее создавать занятия и контролировать результаты класса, а ученику - решать индивидуальные задания, получать обратную связь и повторно отрабатывать ошибки.

Главная ценность проекта заключается в том, что он автоматизирует рутинные действия учителя и делает процесс обучения более персонализированным.
