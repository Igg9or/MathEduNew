# Инструкция по передаче и сопровождению платформы MathEduNew

Этот документ написан для человека, который раньше не занимался Git, сервером, базой данных и технической поддержкой проекта. Его цель - объяснить, как пользоваться платформой как учителю, где находятся основные разделы, как добавлять задания, как обновлять код и как аккуратно работать с базой данных.

## 1. Что это за платформа

MathEduNew - это веб-платформа для проведения уроков математики.

В системе есть несколько ролей:

- `student` - ученик;
- `teacher` - учитель;
- `admin` - администратор школы;
- `platform_admin` - администратор всей платформы.

Учитель создает уроки, добавляет задания, запускает уроки, смотрит результаты и может генерировать домашние задания по ошибкам учеников.

Ученик входит в систему, открывает урок, решает задания, получает проверку, может перерешать ошибки и смотреть прогресс.

## 2. Основные адреса внутри платформы

Адреса ниже указываются относительно домена платформы. Например, если сайт открыт по адресу `https://example.com`, то страница входа будет `https://example.com/login`.

Основные страницы:

- `/login` - вход в систему.
- `/student/dashboard` - кабинет ученика.
- `/teacher/dashboard` - кабинет учителя.
- `/teacher/manage_students` - управление учениками.
- `/teacher/manage_tasks` - раздел учебников и шаблонов заданий.
- `/teacher/edit_lesson/<id>` - редактирование конкретного урока.
- `/teacher/conduct_lesson/<id>` - проведение урока и просмотр результатов.
- `/student/lessons` - список уроков ученика.
- `/lesson/<id>` - страница решения урока учеником.
- `/student/profile` - профиль ученика и перерешивание ошибок.
- `/dev/import-templates` - массовый импорт шаблонов заданий JSON.
- `/dev/playground` - тестовая площадка для шаблонов.
- `/platform/schools` - управление школами, доступно только `platform_admin`.

## 5. Как сохранить изменения и отправить их в GitHub

Эти команды выполняются на компьютере, где редактируется проект.

Сначала перейти в папку проекта:

```powershell
cd D:\MathEduNew-main
```

Проверить, какие файлы изменились:

```powershell
git status
```

Посмотреть сами изменения:

```powershell
git diff
```

Добавить все изменения в будущий коммит:

```powershell
git add .
```

Создать коммит:

```powershell
git commit -m "Краткое описание изменений"
```

Пример:

```powershell
git commit -m "Добавлена инструкция по сопровождению платформы"
```

Отправить изменения в GitHub:

```powershell
git push origin main
```

После этого изменения появятся в репозитории GitHub.

## 6. Как получить свежие изменения из GitHub на локальный компьютер

Если другой человек уже отправил изменения в GitHub, их нужно подтянуть:

```powershell
cd D:\MathEduNew-main
git pull origin main
```

Если Git пишет конфликт, значит один и тот же файл изменили в двух местах. В этом случае лучше не нажимать случайные команды, а попросить технического человека помочь.

## 7. Как обновить код на сервере

Обычно порядок такой:

1. Подключиться к серверу по SSH.
2. Перейти в папку проекта.
3. Выполнить `git pull`.
4. Обновить зависимости, если менялся `requirements.txt`.
5. Применить миграции БД, если менялась структура базы.
6. Перезапустить приложение.

Пример команд:

```bash
ssh user@server_ip
cd /path/to/MathEduNew-main
git pull origin main
```

Если менялся `requirements.txt`:

```bash
pip install -r requirements.txt
```

Если используется виртуальное окружение:

```bash
source venv/bin/activate
pip install -r requirements.txt
```

Перезапуск зависит от того, как именно запущен сервер.

Если используется `systemd`, команда может быть такой:

```bash
sudo systemctl restart mathedu
```

Если используется Render/аналогичный хостинг, может быть включен автоматический деплой после `git push`. Тогда сервер обновляется сам после отправки изменений в GitHub.

Если используется ручной запуск:

```bash
gunicorn app:app
```

В проекте есть `Procfile`:

```text
web: gunicorn app:app
```

Это значит, что на production сервере приложение рассчитано на запуск через Gunicorn.

## 8. Очень важные правила при обновлении сервера

Перед обновлением:

- убедиться, что изменения уже отправлены в GitHub;
- сделать резервную копию базы данных;
- не удалять `.env`;
- не выполнять `git reset --hard`, если вы не понимаете последствий;
- не коммитить реальные пароли, ключи и файлы `.env`;
- после обновления проверить вход учителя и открытие урока.

Минимальная проверка после деплоя:

1. Открыть `/login`.
2. Войти под учителем.
3. Открыть `/teacher/dashboard`.
4. Открыть любой урок.
5. Войти под учеником.
6. Решить одно тестовое задание.

## 9. Настройки `.env`

Файл `.env` содержит секретные настройки. Он должен быть на сервере и на локальной машине, но не должен попадать в GitHub.

Пример структуры из `.env.example`:

```env
OPENAI_API_KEY=your_key_here
DB_NAME=mathdbnew
DB_USER=mathuser
DB_PASSWORD=your_password
DB_HOST=localhost
DB_PORT=5432
```

Что означает:

- `OPENAI_API_KEY` - ключ OpenAI для ИИ-помощника и генерации домашних заданий.
- `DB_NAME` - имя базы данных PostgreSQL.
- `DB_USER` - пользователь PostgreSQL.
- `DB_PASSWORD` - пароль пользователя PostgreSQL.
- `DB_HOST` - адрес сервера базы данных.
- `DB_PORT` - порт PostgreSQL, обычно `5432`.

Реальные значения нужно передавать новому ответственному отдельно: например, в менеджере паролей, а не в файле инструкции и не в сообщении в общем чате.

## 10. Как работает база данных

База данных - PostgreSQL.

Подключение к БД происходит в `app.py` через функцию `get_db()`:

```python
def get_db():
    conn = psycopg2.connect(
        dbname=os.getenv("DB_NAME"),
        user=os.getenv("DB_USER"),
        password=os.getenv("DB_PASSWORD"),
        host=os.getenv("DB_HOST", "localhost"),
        port=os.getenv("DB_PORT", "5432")
    )
```

Основные таблицы:

- `schools` - школы.
- `classes` - классы.
- `users` - пользователи.
- `lessons` - уроки.
- `lesson_tasks` - задания внутри уроков.
- `task_templates` - шаблоны заданий.
- `textbooks` - учебники/разделы шаблонов.
- `student_task_variants` - индивидуальные варианты заданий для учеников.
- `student_answers` - ответы учеников.
- `student_progress` - прогресс учеников.
- `duel_rounds` - раунды дуэли.
- `duel_matches` - матчи дуэли.
- `duel_match_answers` - ответы в дуэли.
- `duel_leaderboard` - итоговая таблица дуэли.

Важная особенность: у большинства данных есть `school_id`. Это нужно, чтобы данные разных школ не смешивались.

## 11. Логины и пароли

Пользователи хранятся в таблице `users`.

Главные поля:

- `username` - логин;
- `password` - пароль;
- `role` - роль пользователя;
- `full_name` - ФИО;
- `class_id` - класс ученика;

Если человек забыл пароль, правильный путь - задать новый пароль через интерфейс или через технического специалиста.

## 12. Роли пользователей

`student`:

- видит свои уроки;
- решает задания;
- перерешивает ошибки;
- смотрит профиль и рейтинг.

`teacher`:

- создает уроки;
- добавляет задания;
- добавляет учеников;
- видит результаты;
- запускает дуэли;
- генерирует домашние задания;
- управляет шаблонами.

`admin`:

- администратор конкретной школы;
- используется для управления школой, если это включено в интерфейсе.

`platform_admin`:

- управляет школами;
- создает учителей и администраторов школ;
- видит раздел `/platform/schools`.

## 13. Как работает урок

Учитель:

1. Заходит в `/teacher/dashboard`.
2. Выбирает класс.
3. Создает урок.
4. Переходит в редактирование урока.
5. Добавляет задания.
6. Запускает или проводит урок.

Ученик:

1. Заходит в `/login`.
2. Вводит логин и пароль.
3. Открывает список уроков.
4. Выбирает урок.
5. Решает задания.
6. Получает проверку.

Когда ученик открывает урок, система генерирует для него индивидуальный вариант задания. Этот вариант сохраняется в таблице `student_task_variants`. Поэтому после обновления страницы ученик видит тот же вариант, а не случайно новый.

## 14. Как работает проверка ответов

Ответ проверяется в несколько этапов:

1. На странице ответ нормализуется.
2. Сервер проверяет ответ через `/api/check_answer`.
3. Для математики используются правила сравнения чисел, дробей, интервалов и выражений.
4. Для алгебраических выражений используется SymPy.
5. Если ответ спорный, может подключаться ИИ.

Основная серверная функция проверки:

```text
_check_answer_core()
```

Она находится в `app.py`.

## 15. Как работает "Решить еще раз"

Если ученик ошибся, он может нажать "Решить еще раз", если учитель не отключил эту возможность.

Серверный маршрут:

```text
/api/generate_retry_task/<task_id>
```

Логика:

1. Берется старый вариант ученика.
2. Из него берется номер набора параметров.
3. Система выбирает парный набор.
4. Генерируется похожее, но другое задание.
5. Повторное решение отмечается как `retry_used`.

Если ученик решил правильно со второй попытки, это может считаться частичным баллом.

## 16. Как добавлять задания вручную в урок

Учитель:

1. Заходит в `/teacher/dashboard`.
2. Выбирает класс.
3. Создает или открывает урок.
4. Нажимает редактирование.
5. Добавляет задание.

Задание может быть:

- простым текстовым заданием с готовым ответом;
- заданием из шаблона;
- заданием с изображением.

Если задание из шаблона, система может выдавать разные варианты ученикам.

Основной раздел:

/teacher/manage_tasks

/dev/import-templates
```

/dev/playground
```

## 18. Структура шаблона задания

Шаблон обычно выглядит так:

```json
{
  "textbook_id": 8,
  "name": "1.б Стоимость товара со скидкой",
  "question_template": "Товар стоит {P} рублей. Скидка {D} рублей. Сколько теперь стоит товар?",
  "answer_template": "{P - D}",
  "answer_type": "numeric",
  "parameters": {
    "P": {
      "type": "choice",
      "values": [1000, 1200, 1500, 2000]
    },
    "D": {
      "type": "choice",
      "values": [250, 300, 400, 500]
    }
  },
  "conditions": "P > D"
}
```

Поля:

- `textbook_id` - ID учебника/раздела, куда попадет шаблон.
- `name` - название шаблона.
- `question_template` - текст задания.
- `answer_template` - формула правильного ответа.
- `answer_type` - тип ответа.
- `parameters` - параметры, которые будут подставляться в задачу.
- `conditions` - условия, которые должны выполняться.

В тексте задания параметры пишутся в фигурных скобках:

```text
{P}
{D}
```

В ответе можно использовать выражения:

```text
{P - D}
{A + B}
{P * N}
{min(A, B)}
```

## 19. Типы параметров

### `choice`

Выбор значения из списка.

```json
"A": {
  "type": "choice",
  "values": [10, 20, 30, 40]
}
```

Если в шаблоне несколько `choice`-параметров с одинаковой длиной массивов, система выбирает один и тот же индекс для всех таких параметров. Это удобно для связанных наборов.

Пример:

```json
"P": { "type": "choice", "values": [1000, 1200, 1500] },
"D": { "type": "choice", "values": [100, 200, 300] }
```

Если выбран первый набор, будет `P=1000`, `D=100`. Если второй - `P=1200`, `D=200`.

### `int`

Случайное целое число.

```json
"A": {
  "type": "int",
  "min": 1,
  "max": 100
}
```

Можно добавить ограничение:

```json
"A": {
  "type": "int",
  "min": 10,
  "max": 100,
  "constraints": [
    { "type": "multiple_of", "value": 5 }
  ]
}
```

### `float`

Случайное дробное число.

```json
"X": {
  "type": "float",
  "min": 1.0,
  "max": 5.0,
  "constraints": [
    { "type": "multiple_of", "value": 0.5 }
  ]
}
```

## 20. Типы ответов

Чаще всего используются:

- `numeric` - число;
- `integer` - целое число;
- `string` - строка;
- `algebraic` - алгебраическое выражение;
- `interval` - интервал.

Если ученик должен написать слово, например "Да" или "Нет", используйте:

```json
"answer_type": "string"
```

Если ответ - выражение:

```json
"answer_type": "algebraic"
```

## 21. Условия `conditions`

Поле `conditions` нужно, чтобы не генерировались плохие задачи.

Примеры:

```json
"conditions": "A != B"
```

```json
"conditions": "P > D"
```

```json
"conditions": "N > 0 and K > 0 and M > 0"
```

Система пробует сгенерировать параметры и проверяет условие. Если условие не выполняется, параметры генерируются снова.

## 22. Шаблоны с изображением

В шаблоне можно использовать изображение.

Для этого есть поля:

```json
"photo_path": "static/uploads/template_photos/file.png"
```

или:

```json
"photo_url": "https://example.com/image.png"
```

Если у шаблона есть фото, текст вопроса может быть пустым, а задание показывается через изображение.

## 23. Как импортировать шаблоны JSON

1. Войти под учителем.
2. Открыть:

```text
/dev/import-templates
```

3. Вставить JSON-массив.
4. Нажать импорт.
5. Проверить, что шаблоны появились в списке.

JSON должен быть массивом:

```json
[
  {
    "textbook_id": 8,
    "name": "Пример 1",
    "question_template": "Вычислите {A} + {B}",
    "answer_template": "{A + B}",
    "answer_type": "numeric",
    "parameters": {
      "A": { "type": "choice", "values": [1, 2, 3] },
      "B": { "type": "choice", "values": [4, 5, 6] }
    },
    "conditions": ""
  }
]
```

Важно:

- `name` должен быть уникальным внутри одного `textbook_id`;
- `textbook_id` должен существовать в базе;
- JSON должен быть валидным;
- кавычки должны быть двойные;
- нельзя оставлять лишние запятые в конце списков.

## 24. Как создать учебник/раздел

Учитель открывает:

```text
/teacher/manage_tasks
```

Там можно добавить учебник/раздел.

При добавлении указываются:

- название;
- описание;
- класс.

После создания учебник получает свой `id`. Этот `id` используется в JSON-шаблонах как `textbook_id`.

## 25. Как работает ИИ

ИИ используется для:

- объяснения решения;
- пошаговой подсказки;
- проверки спорного ответа;
- генерации домашнего задания по ошибкам;
- помощи в дуэльном режиме.

Для работы нужен `OPENAI_API_KEY` в `.env`.

Если ключ отсутствует или закончилась квота, функции ИИ могут выдавать ошибку, но обычные уроки и проверка стандартных ответов должны работать.

## 26. Домашние задания

Учитель может сформировать домашнее задание по ошибкам ученика.

Система:

1. Берет ответы ученика.
2. Находит ошибки.
3. Отправляет данные в ИИ.
4. Получает объяснения и новые задания.
5. Формирует PDF.

PDF сохраняется в папку:

```text
homeworks/
```

## 27. Дуэльный режим

При создании урока можно включить дуэльный режим.

В дуэли:

- учитель создает раунды;
- задает время;
- выбирает задания для раунда;
- запускает дуэль;
- ученики решают задания на время;
- система считает очки;
- победители переходят дальше;
- формируется таблица лидеров.

Основные страницы:

- `/teacher/duel_bracket/<lesson_id>` - сетка дуэли для учителя.
- `/duel_bracket/<lesson_id>` - публичная сетка.
- `/student_duel` открывается через соответствующий урок.

## 28. Резервное копирование базы данных

Перед важными изменениями нужно делать backup.

Пример команды на сервере:

```bash
pg_dump -U DB_USER -h DB_HOST DB_NAME > backup_YYYY_MM_DD.sql
```

Пример:

```bash
pg_dump -U mathuser -h localhost mathdbnew > backup_2026_07_02.sql
```

Восстановление из backup:

```bash
psql -U DB_USER -h DB_HOST DB_NAME < backup_YYYY_MM_DD.sql
```

Восстановление базы - опасная операция. Ее лучше делать только с техническим специалистом.

## 30. Частые проблемы

### Не получается войти

Проверить:

- правильный логин;
- правильный пароль;
- есть ли пользователь в таблице `users`;
- правильная ли роль;
- есть ли `school_id`.

Если пароль забыт, его нельзя посмотреть, нужно задать новый.

### Учитель не видит класс

Проверить:

- создан ли класс в `classes`;
- совпадает ли `school_id`;
- есть ли ученики в этом классе;
- учитель находится в нужной школе.

### Ученик не видит урок

Проверить:

- урок создан для класса ученика;
- ученик относится к этому классу;
- у урока правильный `school_id`.

### Задание не генерируется

Проверить шаблон:

- валидный JSON;
- все параметры из текста есть в `parameters`;
- формула ответа не содержит ошибки;
- `conditions` не делает генерацию невозможной;
- массивы `choice` согласованы по длине, если они должны идти парами.

### ИИ не отвечает

Проверить:

- есть ли `OPENAI_API_KEY` в `.env`;
- не закончилась ли квота;
- доступен ли интернет на сервере;
- нет ли ошибки в логах сервера.

## 31. Минимальный чек-лист передачи новому учителю

Передать:

- ссылку на сайт;
- логин и временный пароль учителя;
- инструкцию по входу;
- инструкцию по добавлению учеников;
- инструкцию по созданию урока;
- инструкцию по добавлению шаблонов;
- GitHub-ссылку, если учитель будет связан с кодом;
- отдельно и безопасно передать доступы к серверу и БД, если они действительно нужны.

Не передавать в открытом виде:

- `.env`;
- пароль от базы данных;
- `OPENAI_API_KEY`;
- доступ к серверу;
- пароль `platform_admin`.

Эти данные лучше хранить в менеджере паролей.

## 33. Что делать, если страшно нажимать команду

Если команда связана с Git и сервером, сначала выполнить:

```bash
git status
```

Если есть сомнения, не выполнять:

```bash
git reset --hard
rm -rf
DROP DATABASE
TRUNCATE
DELETE FROM users
```

Эти команды могут удалить работу или данные.

Безопаснее сначала сделать backup и спросить технического специалиста.
